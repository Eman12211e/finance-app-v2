Practice Trading redesign: mockups for review

Static HTML and CSS only: no JavaScript, no server, no network requests. All figures are placeholders from one consistent simulated session and are labelled as simulated. Fonts render with system fallbacks until Step 2c self-hosts Bricolage Grotesque and Public Sans.

01 App shell and navigation

Primary task
Know what the five sections are and move between them.
Layout hierarchy
Brand, then the five sections (icon and name), then one Learn menu and the profile.
Visible immediately
All five section names, which one is open, the profile.
Needs interaction
The Learn menu (Before you buy, Learn about accounts, Sentiment).
Desktop vs phone
Desktop: one header row. Under 1180 px: icons only (names kept for screen readers). Phone: a five-item bottom bar.
Keyboard and access
Real tablist; one Tab stop; Left/Right/Home/End move between tabs; each tab has a URL hash; skip link; selected tab marked by underline and fill, not color alone.
Less confusing because
Three loose header buttons become one Learn menu, so there is one place to navigate and one place to learn.

02 Practice Trading, desktop (1280 px)

Primary task
See where the practice account stands, place a practice order, advance time.
Layout hierarchy
Left: practice tickers with sparklines. Centre: account strip (value, cash, gain/loss, day controls), then the reserved chart, then positions and history. Right: sticky order ticket.
Visible immediately
Portfolio value, cash, total and realized/unrealized gain/loss, "Day 14 of 120", Next day, the ticket, positions.
Needs interaction
Preview and confirm; Reset (in the ⋯ menu); history filter; choosing a ticker.
Desktop vs phone
Three columns here; on phones everything stacks and the ticket becomes a sheet (03).
Keyboard and access
Ticket stays in view while scrolling; table has a caption and column headers; fills are announced with role="status" toasts; gains and losses always carry an arrow and a sign.
Less confusing because
Every money figure sits on the hatched "Simulated" paper; the fill rule is printed under the estimate; the fill toast says what happened in one line.

03 Practice Trading, phone (390 px)

Primary task
The same as desktop, one-handed.
Layout hierarchy
Account strip and day controls first, chart slot, compact position rows, a full-width Trade button above the bottom navigation.
Visible immediately
Portfolio value, cash, gain/loss, day and Next day, without scrolling.
Needs interaction
Trade opens a bottom sheet with the full ticket; the ⋯ menu holds Reset.
Desktop vs phone
Watchlist and history move below positions; the ticket is a sheet instead of a rail.
Keyboard and access
The sheet is a modal dialog: focus moves into it, Escape or × closes it and returns focus to Trade; touch targets at least 40 px.
Less confusing because
One obvious Trade action instead of a long scrolling page of controls.

04 Order ticket: preview, confirm, queued, rejected

Primary task
Understand exactly what will happen before committing a practice order.
Layout hierarchy
The preview replaces the ticket body in place: the order in one line, a short summary (close, estimate, cash after, when it fills), the optional journal, then Confirm and Back.
Visible immediately
What, how many, the estimate and that it fills at the next open.
Needs interaction
Confirm, Back, the optional journal, cancelling a queued order.
Desktop vs phone
Identical content; on phones it lives in the sheet.
Keyboard and access
Enter previews; Confirm is the default action; the error line is tied to the field with aria-describedby and aria-invalid.
Less confusing because
The words stay the same through the flow (Preview, Confirm practice order, Order queued, Bought …), and the rejection says the amount and the cash available in one line.

05 First visit, before a session starts

Primary task
Understand what this is and start.
Layout hierarchy
One card (what it is, one sentence, market choice, one button), then a three-step "how this works".
Visible immediately
That it is simulated practice with $10,000 that isn't real, and the start button.
Needs interaction
Choosing a practice market (market B arrives in Step 4).
Desktop vs phone
The three steps sit in a row on desktop and stack on phones.
Keyboard and access
The market choice is a radio group; the steps are an ordered list because they are a real sequence.
Less confusing because
It explains the next-open fill rule before the first order, and that progress is saved in this browser only.

06 P4 Analysis toolbox, desktop (1280 px)

Primary task
Add a few well-known indicators to the price chart, mark levels, and understand what each indicator says in plain words.
Layout hierarchy
Chart card: heading and Daily/Weekly, then the toolbar (Indicators, Horizontal line, Trend line, Clear drawings), the readout, the chart with RSI and MACD panes, the legend, the text summary and the TradingView credit. Below it: one explanation card per active indicator, then "Your drawings".
Visible immediately
The chart with up to two lines on the price and two panes, each line named on the chart and in the legend; the current reading of each indicator in words.
Needs interaction
Choosing indicators and preset periods (Indicators menu); drawing; removing drawings.
Desktop vs phone
Same controls; the toolbar wraps and the Indicators menu becomes a sheet on phones (07).
Keyboard and access
Toolbar buttons use aria-pressed / aria-expanded; drawings can be added from a keyboard form and removed from a list; the summary is the chart's text version; lines differ by style (solid, dashed) and carry names, not colour alone.
Less confusing because
Every indicator explains its current value in one sentence, with what it shows, how people read it and what to watch out for, and says that it is education, not a recommendation.

07 P4 Analysis toolbox, phone (390 px)

Primary task
The same on a phone.
Layout hierarchy
Chart card with the wrapped toolbar and panes; the Indicators sheet; drawing banner, drawings list, keyboard form and an explanation card.
Keyboard and access
The sheet is a modal dialog (Done or Escape closes it); "What is this?" jumps to the indicator's card; targets at least 32 px.

08 P4 toolbox states and edge cases

Shown
The Indicators menu at its limit, the drawing-mode banner, a keyboard-form error, RSI above 70, not enough history, flat prices, a weekly view with the week in progress, and an empty drawings list.
For approval
