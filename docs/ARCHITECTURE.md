## 1. What we are building

A beginner-friendly financial education web app. Demo is local, on one laptop, clicked by judges.

**Goal of the app:** Teach. Explain financial facts in plain language so people can think for themselves.
The app never tells anyone what to buy or sell.

**Stack:** Python 3 + Flask · HTML + CSS + vanilla JavaScript (no frameworks, no build step) ·
browser `localStorage` for profile and watchlist · Claude API (Sonnet 5.5) · Finnhub + FMP free tiers ·
real-data demo JSON as fallback.

**Features (7):**
1. Onboarding: age range + risk preference
2. Watchlist: 5 pre-loaded tickers, user can add any US ticker
3. Company snapshot (no AI)
4. Structured earnings summary (numbers from Python, words from Claude)
5. AI chat (educational, grounded in the open ticker)
6. Simulated alerts (generated from real demo data, labeled "Simulated")
7. Disclaimer (always visible) + pre-purchase checklist (static)

**Out of scope:** login, database, deployment, charts, news, real notifications, yfinance at runtime.

## 4. Data flow

```
Browser (localStorage: profile, watchlist)
   │  api.js — every request goes through here
   ▼
Flask route  ── validate input (validation.py) ── bad? → fail(INVALID_...)
   │
   ▼
Service layer
   ├─ snapshot:  market_data.get_snapshot(ticker)
   ├─ earnings:  market_data.get_financials(ticker)
   │               → earnings_service.build_facts(financials, origin) ← Python computes ALL numbers
   │               → ai_service.explain_earnings(facts, profile) ← Claude writes ONLY words
   ├─ chat:      ai_service.chat(message, history, profile, context_facts)
   └─ alerts:    alerts_service.build_alerts(tickers)          ← from demo_stocks.json only
   │
   ▼
routes/envelope.py → { ok, data, source, as_of, error }
```

### Source fallback order (market_data.py)

```
cache hit?                  → return  (source: "cache")
DATA_MODE=live and call OK? → cache it → return (source: "live")
ticker in demo_stocks.json? → return  (source: "demo")
otherwise                   → raise DataNotAvailable
```

A single missing field never triggers a fallback. It stays `null`. Fallback happens only when the whole call fails.

**Provenance rule.** Every cache entry stores `(data, origin, as_of)` where `origin` is `"live"` or `"demo"`.
A cache hit reports `source: "cache"` **only when the stored origin is `"live"`**. Demo-origin entries always
report `source: "demo"` with `as_of = generated_at`, however many times they are served. The user must always
be able to tell demo data from live data by the badge alone.

### Cache TTLs
Quote: 60 s · Profile: 24 h · Financials/earnings: 24 h · AI explanations: 24 h, keyed on `ticker + period + age_range + risk`.

## 7. Locked decisions (do not change without the planner)

| # | Decision | Reason |
|---|---|---|
| 1 | **Python writes numbers, Claude writes words.** Claude output never contains a financial figure. | Makes invented numbers structurally impossible |
| 2 | **Missing value = `null` → UI shows "Data not available."** No estimates, no borrowing from other quarters. | Data integrity |
| 3 | **EPS comparison is labeled "EPS vs. analyst estimate: Above / Below / Equal."** Never a bare "Beat". | The benchmark is the analyst consensus, not the company's own standard |
| 4 | **EPS actual and EPS estimate come from the same source** (Finnhub earnings endpoint). | Adjusted vs. GAAP EPS mixing would create false comparisons |
| 5 | Claude never claims what a specific analyst or firm said. "Analyst average estimate (source: Finnhub)" is a number, not a story. | We have no such data |
| 6 | No news in the MVP. The optional Sentiment Explorer uses only fixed, fictional example statements, labelled as not real news. | Removes AI-generated slanted stories entirely |
| 7 | yfinance runs only in `scripts/build_demo_data.py`, never at runtime. | Unofficial scraper, can break mid-demo |
| 8 | The app only reads `demo_stocks.json` in the contract schema. What produced it does not matter. | The generator can be replaced later with zero app changes |
| 9 | Alerts are generated from real values in `demo_stocks.json`. No hand-written alert figures. | No invented numbers |
| 10 | ETFs (VOO) have no earnings sections. The panel shows a short ETF explanation instead. | ETFs do not report earnings |
| 11 | Snapshot uses no AI. Profile note is one of 3 static texts by risk level (in `profile.js`). | Instant and deterministic |
| 12 | Profile lives only in the browser and is sent with each request. No server state. | No sync bugs |

## 8. Rules for every agent

1. Read `ARCHITECTURE.md`, `API_CONTRACT.md`, and (if your work touches AI) `AI_RULES.md` before coding.
2. Edit only files you own. Report needed changes elsewhere; do not make them.
3. Match the contract exactly: field names, types, nesting, error codes.
4. No new dependencies unless the planner approves. Approved exception: the optional Sentiment Explorer's packages live only in `requirements-sentiment.txt`; the core app and tests never need them.
5. No frameworks. No build step.
6. Never invent, estimate, or hard-code financial figures in code. Real numbers live only in `demo_stocks.json` or come from APIs.
7. Never suppress an exception to make a test pass. Never return fake success.
8. Log with `logging.getLogger(__name__)`. Format: `%(asctime)s %(levelname)s [%(name)s] %(message)s`. Never log keys.
9. Run your tests before reporting done. Report what you tested and what you did not.
10. Commit once your done criteria pass. One commit per agent, message: `[Agent X] <what was built>`.
11. Final report must list: files changed, tests run + results, anything not finished, any change needed in a file you do not own.
